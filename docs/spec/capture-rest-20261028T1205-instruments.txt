What it settles
---------------
1. A series resolves to its open window in one call, which is the thing FIX
   cannot do (docs/open-questions-roll.txt R-Q2):
     BTCD15M -> BTCD15M-BTC26OCT281215-0   status OPEN
     ETHD15M -> ETHD15M-ETH26OCT281215-0   status OPEN

2. One series per call. Repeating the parameter
   (series_ticker=A&series_ticker=B) is HTTP 400; comma-separating them is
   HTTP 200 with zero rows, i.e. it is read as one literal ticker. Two series
   means two calls.

3. price_level_structure is TAPERED_DECI_CENT for both of these series - the
   spec's structure (0.001 below 0.100 and above 0.900, 0.01 between), not
   the tapered-cent grid built on 2026-10-28. See docs/open-questions-gui.txt
   GUI-Q23.

4. The scheduled end does not need the ticker parsed: expected_close_time and
   metadata.market.window_end_time both carry it. close_time is null while the
   instrument is open - it is "most recent transition to CLOSED", not the
   schedule.

5. Fields worth having that nothing else exposes: min_order_size,
   contract_size, position_limit_per_instrument, speedbump_ms, open_interest,
   total_volume, and metadata.market.price_strike with the window's start and
   end times.
