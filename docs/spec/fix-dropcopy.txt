FIX Dropcopy
          FIX DropCopy Gateway API Reference
          FIX wire spec for the CPM (Prediction Markets) drop-copy feed: the message structure and the
          field data provided. Drop-copy is a read-only feed — it delivers execution reports and market
          settlement reports for activity in the session's subscription scope (firm or FCM).

              -​    Session layer: FIXT.1.1
              -​    Application layer: FIX 5.0 SP2 (DefaultApplVerID = 9)
              -​    Baseline: FIX 5.0 SP2, with CPM-specific extensions in the 20000+ / F1–F5 / UMS
                    ranges.

          Supported inbound application messages: LastExecIDRequest (F1) and
          EventResendRequest (F3) only. Other application message types receive a
          BusinessMessageReject(j).

              Authentication uses an API key carried in SenderCompID(49) + passphrase
              (Password(554)) + an HMAC signature (RawData(96) or Text(58)). All three are verified
              on every Logon:

                 -​   the passphrase must match the API key's stored passphrase;
                 -​   the signature must be a valid HMAC-SHA256 (44-character Base64 of a 32-byte digest)
                      over SendingTime + ApiKey + TargetCompID + Password (UTF-8, no
                      separators; ApiKey = SenderCompID(49); SendingTime re-encoded at millisecond
                      precision, TargetCompID = CBPMDC), verified against the API key's secret;
                 -​   SendingTime(52) must be within a ±30-second window;
                 -​   the API key must resolve to an ACTIVE trading user carrying the DROP_COPY
                      permission, and resolve to a firm or FCM subscription scope.

              Any failure disconnects the session. A live session is also disconnected if its authorization is
              later revoked (API key disabled/deleted, or its firm/FCM scope parent changes).
          3. Execution Report (35=8)

          submitted, rejected or FOK-expired, canceled or time-expired, and per-fill trades. Each trade

          originating order's firm and FCM identity; both sides of a trade are reported when both are in
          scope.

          3.1 ExecID composition
          ExecID = (seqId << 1) | sideBit, rendered as the decimal string of that long.

              -​   seqId — the event's monotonic sequence id (so ExecIDs are chronologically ordered,
                   which the resend range in §5 relies on).
              -​   sideBit — 0 for lifecycle events and aggressor/taker fills; 1 for resting/maker fills.

          The side bit disambiguates the two fills produced from a single trade (which share one seqId).
          Lifecycle reports — including speed-bumped, submitted, rejected, canceled, and settlement
          reports — use sideBit = 0. Aggressor fills also use bit 0; resting fills use bit 1.

            3.6 Market Settlement Report (35=UMS)

            and routed to the corresponding firm and FCM drop-copy scopes. If the gateway cannot resolve

            malformed UMS. The report uses the same ExecID / resend space as execution reports
            (MarketSettlementReportID is composed like a lifecycle ExecID — see §3.1). Resent

          4. Fixed-point conventions
          Internal CPM fixed-point values are converted to ordinary FIX decimal numbers using the
          following scales. These scales define numeric precision, not fixed-width text; insignificant trailing
          zeroes may be omitted.


      Quantity                            Decimals                              Range / notes and possible FIX
                                                                                text

      Price                               3                                     0.001–0.999 (YES price; YES +
                                                                                NO = 1.000). Settlement price
                                                                                may be 0 or 1. Possible text:
                                                                                0.55, 0.550, 1.

      Quantity                            2                                     e.g. 1.25 contracts. Possible text:
                                                                                1, 1.25.

      Amount (fees / payout)              6                                     USDC amount. Possible text: 0,
                                                                                0.0495, -2.5.




          5. Event resend (F1–F5)
          Clients recover missed events by ExecID range — not via a session-level
          ResendRequest(2) of application messages. Resent ExecutionReport(8) and
          MarketSettlementReport(UMS) messages carry PossResend(97)=Y.

          Replayed ER and UMS messages preserve the stored application body verbatim, including the
          original TransactTime(60) and report identifiers. The gateway creates a fresh session
                               header, advances the outbound MsgSeqNum(34), refreshes SendingTime(52), and sets
                               PossResend(97)=Y.

                               The resend cursor is scoped to the session's subscription (firm or FCM). ResentEventCount
                               counts every resent application message in the requested range (ER and UMS).

                               LastExecIDRequest (F1) → LastExecID (F2) — query the last ExecID available for the
                               session's scope.

6. Administrative messages
Standard FIXT.1.1 session messages: Heartbeat(0), TestRequest(1),
ResendRequest(2), Reject(3), SequenceReset(4), Logout(5). Reject(3) carries a
SessionRejectReason(373); app-level invalid/unknown inbound messages get a
BusinessMessageReject(j) with BusinessRejectReason(380).
